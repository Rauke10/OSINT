# 3. uv and a standalone Python build

- Status: Accepted
- Date: 2026-05-19

## Context

GLOBEYE is a Python application with a separate React + TypeScript front end.
It needs reproducible dependency resolution, a fast developer setup, and a
build that yields a single installable artifact — the web UI must not require
a separate front-end build step or a Node.js runtime when the tool is used.

## Decision

- **`uv`** is the package and environment manager. The lockfile pins the full
  dependency graph for reproducible installs across Python 3.12 and 3.13;
  `dependency-groups.dev` holds the tooling.
- **`hatchling`** is the build backend (PEP 517). The wheel packages
  `src/globeye`.
- The front end is **built into the package**. `npm run build` emits the
  compiled single-page app into `src/globeye/api/static/`, and FastAPI serves
  those static files. `make install` and the Docker image run the front-end
  build while producing the artifact.

The result is a **standalone** distribution: installing the wheel — or
running the container — provides the CLI, the API and the web UI with no
Node.js runtime and no separate front-end deployment.

## Consequences

- One artifact ships everything; `pip install` and `docker run` just work.
- Building from source needs Node.js 22+ once, at build time only.
- `src/globeye/api/static/` is a generated build output and is git-ignored;
  it is regenerated by `make install`, CI, and the Docker build.
- Contributors use `uv` commands (`uv run …`, `uv sync`); the `Makefile`
  wraps the common ones.
